# WTM — Wind Turbine Maintenance

Настольное приложение для облёта ветропарка дроном. Сценарий работы:

1. **Миссия** — создать на главной: тип, высота полёта, лимиты погоды, профиль дрона.
2. **Ферма и маршрут** — загрузить KML/KMZ с турбинами (или расставить их на карте), построить порядок облёта
   (автоматически, муравьиным или генетическим алгоритмом в фоновом потоке), поправить руками, выгрузить в JSON или KML.
3. **Погода** — прогноз Open-Meteo для фермы на 7 дней, ветер на высотах 10–180 м, порывы, окно вылета по часам
   («можно / на грани / нельзя» с причинами) и выбор часа вылета. Оценка времени и заряда по профилю дрона.
4. **3D-облёт** — проигрывание того же плана полёта, что на карте, в реальном масштабе: высоты транзита и ступиц,
   облёт каждой турбины на безопасной дистанции, скорость и заряд дрона, ротор по ветру часа вылета, карта на земле.
5. **Завершить полёт** — миссия фиксируется: полётные данные больше не меняются, профиль дрона сохраняется снимком.
6. **Дефекты** — загрузить фото облёта: модель YOLO находит дефекты прямо на компьютере (WebGPU, иначе WASM),
   крупные кадры режутся на плитки, находки привязываются к турбинам по GPS из EXIF, их можно проверять и выгружать.
7. **История** — все миссии с поиском и фильтрами, отчёт HTML, архив.

Все данные (миссии, фото, находки) хранятся локально в IndexedDB. В интернет уходят только запросы прогноза,
поиска города и тайлы карты.

## Запуск

Нужен [Node.js](https://nodejs.org) 22 LTS или новее.

```bash
npm install
npm run dev              # веб-версия в браузере: http://localhost:5173
npm run dev:electron     # то же в окне Electron
```

Проверки и сборка:

```bash
npm run check            # типы, линтер, тесты, сборка — должно проходить перед каждым коммитом
npm test                 # только тесты (vitest)
npm run build:electron   # установщик Windows (NSIS) в папке release/
```

## Устройство

```
src/
├── domain/        — предметная логика без интерфейса: типы, план полёта, траектория, погода и допуск к вылету,
│                    статусы миссии, маршрутизация (route/), конвейер детекции (detectionPipeline/). Всё с тестами
├── lib/           — геометрия (локальные метры от центра фермы — одна система координат для карты, маршрута и 3D), KML, коды WMO
├── storage/       — IndexedDB через Dexie: миссии, профили дронов, фото и находки
├── services/      — Open-Meteo, решатель маршрута и движок детекции (запускают воркеры), разбор фото
├── workers/       — фоновые потоки: маршрут, детекция (onnxruntime-web)
├── features/      — части экранов по функциям: mission, route, weather, forecast, simulation, detection, settings
├── pages/         — экраны (грузятся лениво)
├── components/    — общие элементы интерфейса
├── hooks/         — живые запросы к базе
└── i18n/          — переводы ru/en; переводы функций — в i18n/features/<функция>.<язык>.json
electron/          — главный процесс: своя схема app:// вместо file://, одно окно, внешние ссылки — в браузере
public/models/     — модель дефектов (ONNX) и 3D-модель дрона
```

Модели и данные сторонних авторов и их лицензии — в [ATTRIBUTION.md](ATTRIBUTION.md).
